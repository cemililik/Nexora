## Context

T-004 WP4 Audit inbox handler for `ContactGdprDeletedIntegrationEvent` redacts audit
entries matched via `EntityType = "Contact" AND EntityId = <contactId>` — the indexed
path. It explicitly does NOT scan other modules' audit entries (CRM Lead, Documents
Document, Subscription Subscription, etc.) whose `BeforeState` / `AfterState` JSON
columns may contain the erased contact's name/email interpolated into payload
(e.g. "Lead assigned to John Doe <john@example.com>").

This is a **GDPR Article 17 compliance gap**: PII must be erased wherever it appears,
not just where `EntityType=Contact`. The T-004 handler acknowledges this limitation
in its source comment:

> "Payload-scan matches are not reliable across free-form JSON columns."

This task delivers the payload-scan redaction strategy, filed as a follow-up because
it requires cross-module design work (how do modules declare which audit payload
fields carry contact references?) that is out of T-004's scope.

## Acceptance criteria

- [ ] Each module that logs audit entries referencing contacts exposes a
      `IContactReferenceLocator` implementation declaring which JSON payload paths
      may contain contact IDs (e.g. `$.assignedTo.contactId`, `$.owner.contactId`).
- [ ] New `ContactPayloadScanJob` (Hangfire, queue `maintenance`) triggered by
      `ContactGdprDeletedIntegrationEvent` scans audit entries module-by-module using
      each locator's declared paths.
- [ ] Scan produces an additional audit entry with `action = "gdpr_erasure_scan"`
      summarizing per-module rows redacted.
- [ ] False-positive rate measured: documented test suite verifies the scan does not
      redact unrelated rows.
- [ ] Performance target: scan completes within 15 min for a tenant with 10M audit
      rows (benchmarked in integration test against seeded fixture).
- [ ] SPEC updated: `docs/modules/tier-1-core/audit/SPEC.md` §PII retention section.
- [ ] Audit coverage standard updated: `docs/standards/audit-coverage.md` §3 Audit
      row notes the scan obligation.

## Technical notes

- Consider `JsonPath.NET` (`System.Text.Json.JsonPath` preview or `json-everything`)
  for locator path resolution.
- Scan MUST be idempotent — re-running after partial completion must not duplicate
  redaction markers. Inbox guard pattern + per-entry `redacted_at` timestamp.
- CRM, Documents, Subscription, Fundraising, Finance are candidate consumers at
  module registration.
