## Context

Add an optional `ContactId?` FK on the `User` entity so an admin can link a human user to
an existing contact for a 360° view (e.g. a staff member who is also a donor). The link
is **never automatic** — system users (API clients, bots) must not create contacts.

This task is co-designed with Phase 2 CRM, which introduces a "Staff" contact type. The
Identity↔Contacts integration must not violate module boundaries — use an integration
event (`UserContactLinkedIntegrationEvent`) rather than cross-module direct calls.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.6
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.6 item 1
- Related ADRs: ADR-001 (modular monolith boundaries), ADR-014 (distributed consistency)

## Acceptance criteria

- [ ] `User.ContactId` is nullable and indexed.
- [ ] Admin UI exposes "Link to contact" on the user detail page, permission-gated
      (`identity.users.link_contact`).
- [ ] Linking emits `UserContactLinkedIntegrationEvent` via outbox.
- [ ] System-user accounts cannot be linked (validator rejects).
- [ ] Unit + integration tests.
- [ ] Locale: `lockey_identity_user_link_contact_*` keys present in en + tr.

## Technical notes

- Keep the direction one-way: Users references Contacts (already allowed per tier rules,
  both are Tier-1).
- No cascade delete; unlink on `ContactGdprDeletedIntegrationEvent`.
- "Staff" contact type comes from CRM in Phase 2; do not block on it — link to any
  contact in 1.5.

### Design decisions

- **FK type:** `Guid? ContactId` on `User` (raw Guid, not `Contacts.ContactId` VO — module boundary). Rationale: Identity ↔ Contacts are both Tier-1; cross-module types stay in SharedKernel or use primitive IDs.
- **System-account detection:** `User.IsSystemAccount` computed property checks `KeycloakUserId.StartsWith("service-account-")` (Keycloak service-account convention). Validator rejects link requests for system accounts.
- **Cascade:** No cascade delete. On `ContactGdprDeletedIntegrationEvent` receipt, Identity inbox handler sets `User.ContactId = null`. **This closes T-004's known limitation.**
- **Permission:** `identity.users.link_contact` — new key, seeded in `IdentityModuleMigration`.
