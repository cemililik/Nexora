## Context

T-004 WP3 Notifications handler for `ContactGdprDeletedIntegrationEvent` scrubs
`Notification.BodyRendered` to the placeholder `[REDACTED]` instead of `null`.
The Notifications SPEC §PII retention policy (added 2026-04-22) specifies that
hot retention ends at 30 days and cold storage sets `body_rendered` to `null` —
but the current column is `IsRequired()` (non-nullable), so we cannot honor the
`null` contract without a schema change.

The placeholder approach works operationally (no PII leaks) but creates a minor
SPEC drift: a GDPR audit question "why is the body column still populated?" has
to be answered with "it's the placeholder, not real content" — a weak answer when
compared to "it's null".

## Acceptance criteria

- [x] Migration: `ALTER TABLE notifications_notifications ALTER COLUMN "BodyRendered"
      DROP NOT NULL;` added to `DevelopmentSeed.ApplySchemaUpdatesAsync`. Verified
      manually against the dev tenant schema (column reports nullable after ALTER).
- [x] EF configuration: `builder.Property(n => n.BodyRendered).IsRequired(false);`.
- [x] `Notification.ScrubRenderedBody()` sets `BodyRendered = null` instead of
      `PiiRedactedPlaceholder.Value`. Subject keeps the placeholder (column stays
      NOT NULL — listing UX depends on it).
- [x] Existing anonymize/hard-delete tests updated to assert `null` not
      placeholder (`ContactGdprDeletedIntegrationEventHandlerTests`).
- [x] `Notification.BodyRendered` property is now nullable (`string?`) end-to-end:
      entity, DTO (`NotificationDetailDto`), and EF config. Query projection
      carries the null through naturally.
- [ ] Recurring job `notifications:purge-rendered-bodies` (declared in SPEC, not
      yet implemented) — **out of T-017 scope**; this task only unblocks that job
      by making the column nullable. Tracked separately in the Notifications
      backlog.
- [x] SPEC updated: the `body_rendered = NULL` cold-storage contract now references
      T-017, and the GDPR erasure bullet documents the null-body / placeholder-subject
      split so a future reader understands the asymmetry.

## Technical notes

- The purge job is a separate deliverable; this task only unblocks it.
- Coordinate with any analytics / reporting queries that may assume non-null
