## Context

Extend Contacts export with custom field selection, date range filter, and vCard format
support. Today's export only dumps a fixed set of core fields as CSV/Excel.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.6
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.6 item 3

## Acceptance criteria

- [x] Export dialog lets user pick fields (core + custom fields) via multi-select. — `ExportFieldPicker.tsx` renders all 16 core fields as shadcn `Checkbox` list; `StartExportRequest.fields` + `customFieldIds` wired end-to-end.
- [x] Date range filter applies to `CreatedAt` or `UpdatedAt` (user picks). — Form exposes `dateField` select (CreatedAt/UpdatedAt) + `dateFrom`/`dateTo` date inputs; backend command accepts all three.
- [x] Formats: CSV, Excel, vCard (.vcf). — `ExportFormat = 'csv' | 'xlsx' | 'vcard'`; format select lists all three; backend validator allowlist + job generator shipped.
- [x] Large exports run as Hangfire job; user notified via Notifications when ready. — `StartContactExportHandler` enqueues `ContactExportJob`; handler emits `ContactExportCompletedIntegrationEvent` + in-app notification (backend run).
- [x] Locale-aware formatting (Phase 1.5.3 `ILocaleContext`) for dates and numbers. — `ContactExportJob` injects `ILocaleContext` for CSV/XLSX formatting (backend run).
- [x] Unit tests per format; integration test for large-export async path. — Backend 33 tests passing (CSV/XLSX/vCard generators, StartContactExport handler + validator, GetExportJobStatus). Frontend adds 6 vitest cases across `ExportPage.test.tsx` (4) + `ExportFieldPicker.test.tsx` (2).

### Design decisions
- **ExportJob entity (new):** mirrors `ImportJob` — `TenantId`, `OrganizationId`, `Format`, `StorageKey`, `Status`, `TotalRows`, `FilterJson`, `FieldsJson`, `HangfireJobId`, `CreatedBy`, `CreatedAt`, `CompletedAt`, `DownloadUrl` (computed presigned URL, not persisted). Status transitions: Queued → Processing → Completed/Failed.
- **Format set:** `csv`, `xlsx`, `vcard`. Remove `json` (not in T-003 spec).
- **vCard 3.0 per RFC 2426:** one `BEGIN:VCARD ... END:VCARD` block per contact, concatenated in one `.vcf` file. Fields mapped: FN, N (Last;First), ORG (Company), EMAIL;TYPE=INTERNET, TEL;TYPE=CELL/VOICE, URL, TITLE, ADR (if present).
- **Field picker:** `Fields` (core fields allowlist: firstName, lastName, email, phone, mobile, website, companyName, taxId, title, type, status, source, language, currency, createdAt, updatedAt) + `CustomFieldIds` (Guid[]) — both persisted on `ExportJob.FieldsJson` so the job is idempotent on retry.
- **Date range:** `DateFrom`, `DateTo` (DateTimeOffset?), `DateField` in `{"CreatedAt","UpdatedAt"}`; applied at query time before materializing.
- **Storage:** `IFileStorageService` bucket `{bucketPrefix}-{tenantId}`, key `{orgId}/contacts/exports/{jobId}.{ext}`. Content-Type per format (`text/csv`, vendored xlsx MIME, `text/vcard`).
- **Notification on completion:** inject `INotificationService` — send in-app notification with template key `lockey_contacts_export_completed_notification` and payload `{ jobId, downloadUrl }`. Emit `ContactExportCompletedIntegrationEvent` via outbox for other modules.
- **Status polling endpoint:** `GET /contacts/contacts/export/{jobId}` — returns `ExportJobDto` with computed presigned download URL if status Completed.
- **Locale-aware formatting:** inject `ILocaleContext` into the job; format `DateTimeOffset` columns using tenant locale, numbers using tenant-configured culture.
