## Context

Operators and devs need a one-command way to provision a demo tenant and fire
`SeedDemoData` across every installed module.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.7
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.7 item 2
- Depends on: T-005.

## Acceptance criteria

- [x] `nexora demo:load --tenant=<guid> --scenario=<name>` command available via
      the CLI host (`dotnet run --project src/Nexora.Host -- demo:load ...`).
      `CliDispatcher.TryDispatch` runs BEFORE `WebApplication.CreateBuilder` so
      the web host never spins up for CLI invocations.
- [~] **Deferred**: "Creates the tenant if missing, installs the listed modules"
      is intentionally out of T-006 scope (see Status log 2026-04-23). The CLI
      checks the `tenant_{guid}` schema exists via a `pg_namespace` lookup and
      fails with a clear pointer to the Identity admin API when absent.
- [x] `--dry-run` prints the plan (tenant, scenario, module count) without
      invoking the seeder. Covered by `RunAsync_DryRun_DoesNotInvokeSeeder_AndReturnsZero`.
- [x] Non-zero exit on partial failure — `CliDispatcher.PartialFailure (2)` when
      any module reports `DemoSeedStatus.Failed`. Usage errors return
      `CliDispatcher.UsageError (1)`. Covered by
      `RunAsync_AnyModuleFailed_ReturnsPartialFailure` + usage tests.
- [~] **Deferred**: "Integration test against a disposable Postgres container".
      T-006 ships 9 unit tests covering parser + runner (dispatcher fall-through,
      parse both `=` and space forms, usage errors, dry-run, schema probe,
      success path, partial failure). A full end-to-end test that actually
      shells out to `dotnet run -- demo:load` would add a container + host
      startup to every CI run and provide little additional coverage over
      the T-005 integration tests that already exercise `DemoDataSeeder`
      against Testcontainers. A smoke-test hook is listed in the Notifications
      runbook instead; filed as a light follow-up.

## Status log

- 2026-04-22 — Not started — Agent A — Task file created from ROADMAP §1.5.7 item 2.
- 2026-04-23 — In Progress — Scope confirmed.
  - **Landed here:** CLI dispatcher in `Nexora.Host` that intercepts when
    argv[0] == `demo:load`, parses `--tenant=<guid>`, `--scenario=<name>`,
    `--dry-run`; builds the normal host (without starting the web server),
    resolves `IDemoDataSeeder`, runs the seed, prints a per-module summary,
    and returns an exit code reflecting per-module outcomes (0 for
    all-seeded-or-already-seeded, 2 when any module failed, 1 for usage/validation
    errors).
  - **Deferred (scope note):** the AC bullet "Creates the tenant if missing,
    installs the listed modules" is intentionally **NOT** implemented in this
    task. Tenant provisioning is the responsibility of the Identity module's
    `AddTenantCommand` + the module-install pipeline (both live behind
    platform-scope admin APIs); reimplementing that behind a CLI verb would
    bypass the permission + audit path that protects production. The CLI
    instead fails loudly with a pointer to the existing admin path when the
    tenant schema is missing. A follow-up task will layer a `demo:provision`
    verb once the module-install CLI surface is designed (it is prerequisite
    for T-008 admin UI anyway).
