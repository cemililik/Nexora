## Context

`tools/check-schema-drift.py` (introduced alongside
`docs/standards/schema-migration.md`) compares every EF entity's
mapped properties against the actual Postgres tenant schema and
exits non-zero on drift. It is the drift detector for the dev
tenant — exactly the kind of check that would have caught the T-021
`HasFilter` drift earlier if we had been running it in CI.

Problem: it is manual. No one runs it, so drift accumulates until a
fresh Testcontainers run (T-018) surfaces it. T-024 wires the script
into the test suite so the detector runs automatically — but
carefully. A Python + running-Postgres dependency on every PR CI run
is disproportionate, so the wrapper is **opt-in**: the test is
skipped unless `NEXORA_SCHEMA_DRIFT_ENABLED=1` is set. Local devs can
opt in; nightly CI can set the flag; default PR CI stays fast.

## Technical notes

- Works on the dev tenant schema
  (`tenant_00000000-0000-0000-0000-000000000001`). The script's
  default suffices; no test-side overrides needed.
- Requires the dev docker compose to be running — the script uses
  `psql` against `localhost:5432`. The env-var gate ensures the test
  never tries this on a stock CI runner.
- Stdout is captured and rendered verbatim in the failure message
  so a CI log shows exactly which columns / entities drifted.
- Python `3.11+` already required by the script itself; we don't
  introduce a new version floor.
