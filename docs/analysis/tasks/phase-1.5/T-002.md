## Context

The current Contacts CSV/Excel import assumes a fixed column order. Users with
non-standard exports (e.g. vendor CRMs, Excel-from-the-field) must hand-edit headers
before uploading. Replace this with a three-step wizard.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.6
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.6 item 2

## Acceptance criteria

- [x] Step 1 — upload → preview first 5 rows with detected headers.
      [`POST /import/preview` + `ContactImportPreviewDto`]
- [x] Step 2 — user maps each source column to a Contact field via shadcn Select
      (no native `<select>` per UX_UI_STANDARDS).
      [`ImportColumnMapping.tsx` component]
- [x] Step 3 — validation report (row-level errors), then confirm import.

      [`[Queue("bulk")]` + `[DisplayName("contacts:bulk-import")]`]

      [parser tests + validate tests + job tests, backend 138/138 ∪ frontend 7/7]

      keys added with parity]

### Design decisions
- **Dynamic row shape:** Parser returns `List<IReadOnlyDictionary<string, string?>>` keyed by detected headers. Handler applies `ColumnMapping` (source header → Contact field) to project into `ContactImportRow`.
- **Mapping persistence:** `ImportJob.ColumnMappingJson` (nullable string, JSON map) — set at confirm step. Additive column.
- **Preview endpoint:** `POST /contacts/import/preview` — body `{ storageKey, fileFormat }` — returns `{ headers: [], rows: [...first5] }`. Stateless; does NOT create an ImportJob.
- **Validation endpoint:** `POST /contacts/import/validate` — body `{ storageKey, fileFormat, columnMapping }` — returns `{ totalRows, errorCount, errors: [{ rowNumber, errorKey, fieldName? }] }`. Stateless.
- **Confirm step:** `POST /contacts/import` (existing) extended to accept `columnMapping` dictionary. Job consumes mapping.
- **Duplicate matcher:** Extract `IContactDuplicateMatcher` from existing inline logic in `ContactImportJob.cs:96-106`; reuse from handler. Interface in `Domain/Services/` (or `Application/Services/`); implementation in `Infrastructure/`.
- **Hangfire queue:** `[Queue("bulk")]` attribute on `ContactImportJob.ExecuteAsync` (NexoraJob supports this via base). Job name descriptor `contacts:bulk-import` configured via `JobDisplayName` attribute or similar — verify by grepping other Hangfire jobs.
- **`catch(Exception)` in `ContactImportJob.cs:169`:** CLAUDE.md violates cleanup — remove the broad catch; rely on NexoraJob base class exception handling. If the existing catch is intentional (status transition on failure), replace with specific catches (IOException, FormatException, …).
