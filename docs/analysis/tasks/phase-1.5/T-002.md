## Context

The current Contacts CSV/Excel import assumes a fixed column order. Users with
non-standard exports (e.g. vendor CRMs, Excel-from-the-field) must hand-edit headers
before uploading. Replace this with a three-step wizard.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.6
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.6 item 2

## Acceptance criteria

- [ ] Step 1 — upload → preview first 5 rows with detected headers.
- [ ] Step 2 — user maps each source column to a Contact field via shadcn Select
      (no native `<select>` per UX_UI_STANDARDS).
- [ ] Step 3 — validation report (row-level errors), then confirm import.
- [ ] Import runs as a Hangfire job (`contacts:bulk-import`) per INFRASTRUCTURE_STANDARDS.
- [ ] Emits `ContactImportCompletedIntegrationEvent` on finish.
- [ ] Unit + integration tests covering malformed CSV, header mismatch, duplicate handling.
- [ ] Locale: `lockey_contacts_import_*` keys in en + tr.

## Technical notes

- Wizard state kept client-side until final submit; backend only receives mapping + file
  ID (MinIO presigned pattern per API_INTEGRATION_STANDARDS §11).
- Duplicate detection uses existing Contacts matcher — do not re-implement.
