## Context

Demo tenants accumulate over time (sales demos, QA runs). Provide a command and matching
admin action to remove demo content — or the entire demo tenant — idempotently.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.7
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.7 item 5
- Depends on: T-005.

## Acceptance criteria

- [x] `nexora demo:clean --tenant=<slug>` CLI command wipes demo-seeded rows (identified
      by the `demo_seed_marker` table from T-005).
- [x] `--drop-tenant` flag deprovisions the entire tenant schema (gated on
      explicit `--yes` non-interactive confirmation — no TTY prompt, per the
      T-009 implementation note, so the CLI stays scriptable).
- [ ] Admin UI button mirrors the CLI (permission-gated) — **[→T-008]** shipped
      in sibling task T-008 (`CreateDemoEnvironmentDialog` on TenantDetailPage).
- [x] Cleanup is idempotent and safe to run on a tenant that has mixed real + demo data
      (only demo-marked rows are removed).
- [ ] Integration test covers mixed-data tenant cleanup — **[→Phase-2]**
      Testcontainers-backed integration pass is deferred; orchestrator-level
      unit tests (`DemoDataCleanerTests`) are the floor for now.

## Technical notes

- Uses the sanctioned "module uninstall / orphan cleanup" hard-delete path (per
  CLAUDE.md soft-delete rules).
- Emits `TenantDeprovisionedIntegrationEvent` when `--drop-tenant` is used, for
  downstream modules to clean up tenant-scoped external state (MinIO buckets, Keycloak
  realm).

  - **Scope.** `IModule.CleanDemoDataAsync` default no-op DIM (symmetric

  - **Testing.** 6 unit tests in `DemoDataSeederTests` for the cleaner +
    10 unit tests in `DemoCleanCommandTests` for the verb; 28 new
    lockeys with en + tr parity verified via
    `CliLocalizationParityTests`. A Testcontainers-backed integration
    pass covering the mixed-data tenant case (AC#5) is filed as a
    Phase 2 follow-up — the orchestrator-level unit tests are the
    coverage floor for now.
  - **Docs.** New `docs/guides/cli.md` §3.3 covers the verb, flag
    matrix, and examples.
  - **Scope carry-over.** AC#3 (admin-UI mirror) is intentionally
    delivered by T-008, not this task.
  - **Known limitation — `--drop-tenant` event delivery.**
    `TenantDeprovisionedIntegrationEvent` is published via `IEventBus`
    directly (at-most-once), NOT via the transactional outbox, because
    the outbox table per the current design lives INSIDE the tenant
    schema being dropped. On a Dapr/Kafka publish failure the signal is
    lost; operators must kick off external-system cleanup (MinIO,
    Keycloak) manually in that case. **Phase-2 follow-up:** introduce a
    platform-level (tenant-independent) outbox so `--drop-tenant` can
    use the transactional path like every other event.
