# T-018: Verify `NexoraJob` tenant context + org propagation for tenant-scoped seed

## Context

Two related gaps surfaced during T-004 maintainer review:

1. **`GdprHardDeleteJob` tenant context propagation.** The Hangfire job relies on
   `NexoraJob<TParams>.RunAsync` setting tenant context before `ExecuteAsync` is
   called. The base class sets `tenantContextAccessor.SetTenant(parameters.TenantId,
   parameters.OrganizationId)`, and the `DbContext` reads the resolved schema in
   `OnModelCreating`. This should route the job to the correct tenant schema, but
   the path was not exercised by the T-004 tests (tests use InMemory provider
   without real schema routing).

2. **`ContactsModuleMigration.SeedAsync` org argument missing.** The migration
   calls `accessor.SetTenant(ExtractTenantId(schemaName))` — one-arg overload.
   `ITenantConfiguration.SetAsync` may or may not require an organization id
   depending on backend implementation. If the config store is org-scoped and
   receives `null`, it will throw `InvalidOperationException` at seed time.

Both need an integration test + possibly an API contract clarification on
`ITenantConfiguration` (tenant-scoped vs tenant+org-scoped keys).

## Status log

- 2026-04-23 — Not started — Filed as T-004 follow-up per maintainer review
  (Findings 15, 16).
- 2026-04-23 — **Discovery (filed as T-021 for triage):** Running the new
  integration test against a fresh Postgres 17 container surfaced a pre-existing
  drift — `ContactTagConfiguration` and `ContactCustomFieldConfiguration` both
  declare `HasFilter("\"IsDeleted\" = false")` on unique indexes, but the
  underlying entities (`ContactTag`, `ContactCustomField`) extend `Entity<T>`,
  not `AuditableEntity<T>`, so they have no `IsDeleted` column. The live dev
  database works only because its schema pre-dates the filter and has been
  patched by hand since. A clean `GenerateCreateScript()` fails with
  `42703: column "IsDeleted" does not exist`. The integration test works around
  the drift by running DDL statement-by-statement and skipping 42703 errors; the
  filters themselves need removing in a follow-up so future Testcontainers-based
  tests don't need the same workaround. Not a T-018 blocker but recorded here so
  the maintainer can decide whether to spin a mini-fix task or fold it into a
  Contacts config audit.
- 2026-04-23 — In Progress — Mapped scope: (1) new Testcontainers integration
  test exercising two-tenant schema routing for `GdprHardDeleteJob`;
  (2) architecture guard that `ExecuteAsync` can never run before
  `SetTenant`; (3) XML-doc contract on `ITenantConfiguration` declaring it
  tenant-scoped (no org argument needed); (4) confirming comment on
  `ContactsModuleMigration.SeedAsync`; (5) audit-coverage matrix entry for
