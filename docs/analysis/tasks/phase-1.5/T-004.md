## Context

The current GDPR deletion flow only anonymizes PII and soft-deletes the contact. GDPR
Article 17 requires **physical removal**. This task adds a true hard-delete path with
cross-module cleanup, while preserving consent records as legal evidence (Article
17(3)(e)).

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.6
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.6 item 4
- Plan doc: `.claude/plans/gdpr-hard-delete.md` (legacy location; migrate if still present)
- Related ADRs: ADR-008 (GDPR deletion strategy), ADR-014 (distributed consistency)

## Acceptance criteria

- [ ] `ExecuteDeleteAsync()` called in FK-safe order for 9 child entities
      (ContactAddress, ContactNote, ContactCustomField, ContactTag, ContactRelationship,
      CommunicationPreference, ContactActivity, ConsentRecord, Contact).
- [ ] `ConsentRecord` rows are **anonymized** (not deleted) per Article 17(3)(e).
- [ ] `ContactGdprDeletedIntegrationEvent` emitted via outbox for cross-module cleanup:
      Documents (`LinkedEntityId` nullify; signature recipient PII anonymize),
      Notifications (recipient address anonymize), Audit (before/after PII scrub).
- [ ] GDPR Export includes `CommunicationPreference` and `ContactRelationship` data.
- [ ] Tests use SQLite InMemory provider for `ExecuteDeleteAsync` support.
- [ ] Audit trail records the erasure action with `erased_by` + timestamp.
- [ ] Locale: `lockey_contacts_gdpr_erasure_*` keys in en + tr.

## Technical notes

- Hard delete is one of the three sanctioned hard-delete paths in CLAUDE.md (alongside
  join-table reconciliation and module uninstall).
- Cross-module consumers must use the inbox pattern (ADR-014) for idempotency.
- Coordinate un-linking with T-001 (`User.ContactId` must become null).
