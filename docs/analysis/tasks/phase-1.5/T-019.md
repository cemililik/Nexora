# T-019: Organization-scoped compliance config with platform caps

## Context

ADR-0025 introduces a 3-tier config resolver (platform cap → tenant default → org
override) to replace the current tenant-global `platform_tenant_config`. The first
real consumer is GDPR hard delete (T-004 / ADR-008), whose feature flag
`gdpr.hard_delete.enabled` must move from tenant scope to org scope so multi-org
tenants with mixed jurisdictions can set their own posture — while preserving a
platform-level cap so the operator can force or forbid the setting.

The tenant-level management surface is being retired from the admin panel as NMP
takes over (MANAGEMENT_PORTAL.md §7 Admin Panel Changes). Any remaining tenant-wide
knobs in the admin panel are a migration debt; org-scoped knobs are the correct
long-term home.

- [x] `IConfigurationResolver` interface added in
      `Nexora.SharedKernel.Abstractions.Configuration` with `GetAsync<T>`,
      `SetOrgOverrideAsync<T>`, `ClearOrgOverrideAsync`, plus diagnostic

## Technical notes

- **Why a separate `IConfigurationResolver` (not overloaded methods on
  `ITenantConfiguration`):** signature churn would touch every existing caller.
  A new interface lets us migrate lazily and keeps `ITenantConfiguration` as a
  stable shim during Phase 1.5.
- **Storage placement:** both new tables live in the **tenant schema**, not
  `public`. Even though the table prefix is `platform_`, that's legacy naming
  (`platform_tenant_config` is also tenant-scoped today). We're not introducing
  a new prefix in this task; future cleanup tracked separately.
- **`ComplianceCap` wire format:** entitlements JSON in
  `platform_license_cache.EntitlementsJson` gains a sub-object
  `compliance.caps.<key> = { "allowed": bool, "forced": bool }`. Extends the
  existing NMP→CRM channel rather than opening a new one.
- **Audit vs GdprErasureAudit:** distinct concerns. `GdprErasureAudit` records
  erasure executions; `platform_compliance_policy_audit` records policy toggles.
  Don't merge — an auditor asking "who turned hard-delete on and when?" should
  get a clean answer without wading through erasure rows.
- **Cache TTL:** 2 min L1 matches `ICacheService` convention. Invalidation on
  `SetOrgOverrideAsync`/`ClearOrgOverrideAsync` and on NMP entitlements push
  (the existing `entitlements.updated` cache key already exists — hook into it).
- **Migration order in `ApplySchemaUpdatesAsync`:** both new tables are
  independent — add them after the existing contacts/GDPR block, before the
  tail `ALTER` statements. Pattern already documented in
  `docs/standards/schema-migration.md` §2.
- **NMP deferred work:** `NmpComplianceCapProvider` and the NMP-side editor ship
  in NMP.2. This task only ensures the SaaS runtime is **ready** for NMP —
  `NullComplianceCapProvider` is the default until then.
