## Context

Phase 2 modules need a consistent way to declare demo data. Extend the `IModule` contract
with an optional `SeedDemoData(ITenantContext, CancellationToken)` method so each module
owns its demo content and avoids a central seeding god-object.

- Phase file: `../../roadmap/phases/phase-1.5-bridge.md` §1.5.7
- Legacy reference: `docs/roadmap/ROADMAP.md` §1.5.7 item 1
- Related ADRs: ADR-001 (modular monolith), module system contract in
  `docs/architecture/MODULE_SYSTEM.md`

## Acceptance criteria

- [ ] `IModule.SeedDemoData()` method added with a default no-op implementation.
- [ ] `DemoDataSeeder` orchestrator resolves installed modules and invokes each in order.
- [ ] Idempotent: re-running against an already-seeded tenant is a no-op (keyed by a
      `demo_seed_marker` table).
- [ ] Unit tests covering ordering and idempotency.
- [ ] Architecture test: no module bypasses `SeedDemoData` to seed another module's data.

## Technical notes

- Each module produces tenant-scoped data; no cross-module coupling.
