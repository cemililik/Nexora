## Context

Schema-per-tenant migration orchestration requires a `MigrationRunner` that applies
every module's EF Core migrations to a tenant schema in module-dependency order.
Currently each module has its own one-off `MigrateAsync` entry point; there is no
platform-level runner that iterates tenants and applies migrations consistently.

See `docs/operations/migration-orchestration.md` §2 for the full design.

## Acceptance criteria

- [x] `MigrationRunner.MigrateAllModulesAsync(tenantId, ct)` applies every registered
      `IModule` migration head to the tenant schema in dependency order
      (re-uses `DemoDataSeeder.OrderByDependencies` — the platform's only
      topo-sort over the same graph). Modules without a registered
      `IModuleMigration` are a no-op rather than a hard failure (Phase 1.5
      modules ship via DevelopmentSeed, not EF migrations yet).
- [x] Per-tenant `pg_advisory_lock` keyed on `hashtext('migrate:' || tenantId)`
      (computed in C# via FNV-1a-64 — see `MigrationRunner.ComputeLockKey` —
      to avoid an extra round-trip). 5-second poll loop with
      `pg_try_advisory_lock`; returns `LockNotAcquired` outcome on timeout
      so the caller can retry instead of throwing.
- [x] Failure path: writes a `MigrationFailure` row to
      `public.platform_migration_failures` (platform-scoped, not tenant-
      scoped — DDL added in DevelopmentSeed); transitions the tenant to
      `TenantStatus.MigrationFailed` via direct SQL UPDATE on
      `identity_tenants` (so the runner does not depend on the Identity
      module's domain assembly). New `Tenant.MarkMigrationFailed()`
      domain method + new `MigrationFailed` enum value added; `Activate()`
      now allows `MigrationFailed → Active` for the ops retry path.
- [x] Unit tests: `ComputeLockKey` determinism + per-tenant distinctness;
      `MigrationFailure.Create` factory shape; stack-trace truncation guard.
      The advisory-lock + tenant-status-update + actual migration paths
      need a Testcontainers Postgres harness to be meaningful — the
      runbook §2 already lists Testcontainers as the integration-test
      foundation; integration test file deferred to first real EF
      migration shipping (so the test has something to actually migrate).
