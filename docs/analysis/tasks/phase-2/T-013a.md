## Context

[T-013](T-013.md) shipped the `platform:audit-migration-drift` Hangfire job, but its AC4 said "Emits `platform.migration.drift.detected` integration event **via outbox**." The implementation publishes via `IEventBus` directly because the platform-level outbox infrastructure does not exist — the only outbox today is per-tenant (`{schema}.outbox_messages` polled by `OutboxProcessor` per active tenant). Building out the platform-outbox plumbing inside T-013 would have expanded scope significantly, so this follow-up tracks the missing infrastructure as a stand-alone work package.

The same gap will block any future platform-level integration event (license rotation alerts, NMP-side notifications, cross-tenant operator events, …) — fixing it once unblocks an entire class of features.

## Current mitigation

Drift evidence already lives in `platform_migration_drift` indefinitely (append-only forensic log; see [`MigrationDriftLogDbContext`](../../../../src/Nexora.Infrastructure/Migrations/MigrationDriftLogDbContext.cs)). Operators query the table directly during ops triage. The worst case of a dropped `IEventBus.PublishAsync` is therefore a **missed alert** — not lost data — which is operator-tolerable for the audit window between this task landing and T-013a delivering reliable delivery.

## Acceptance criteria

- [ ] **Schema.** `public.outbox_messages_platform` table created via additive DDL in `DevelopmentSeed.ApplySchemaUpdatesAsync` and via an EF migration when the production schema-migration pipeline picks it up. Same column shape as the per-tenant `outbox_messages` (Id, EventType, EventPayload, TenantId, CreatedAt, ProcessedAt, RetryCount, Error) so the existing `OutboxMessage` entity + `OutboxMessageConfiguration` can be re-used by a new `PlatformOutboxDbContext`.
- [ ] **DbContext.** `PlatformOutboxDbContext` lives in `Nexora.Infrastructure/Persistence/Outbox/` next to the existing outbox infra; uses `HasDefaultSchema("public")` and maps `OutboxMessage` to `outbox_messages_platform`.
- [ ] **IOutbox registration.** `IOutbox<PlatformOutboxDbContext>` registered as `OutboxService<PlatformOutboxDbContext>`, plus a marker interface `IPlatformOutbox : IOutbox` (or DI keyed-services equivalent on .NET 8+) so platform-level callers (drift job, license rotation, future events) can resolve the platform outbox without colliding with per-tenant outbox registrations.
- [ ] **OutboxProcessor scope.** `OutboxProcessor.ProcessAllTenantsAsync` extended to also poll `public.outbox_messages_platform` after the per-tenant pass — single additional `await ProcessTenantOutboxAsync("public", connectionString, eventBus, ct)` call, gated by a setting so on-prem deployments without platform events can opt out.
- [ ] **Migrate the T-013 publish path.** `PlatformAuditMigrationDriftJob` switches from `IEventBus.PublishAsync` to `IPlatformOutbox.EnqueueAsync` inside the same `SaveChangesAsync` transaction as the drift-row writes, restoring strict AC4 compliance ("via outbox").
- [ ] **Tests.** Integration test seeding a platform-level outbox row + asserting `OutboxProcessor` drains it; T-013's `PlatformAuditMigrationDriftJobTests.ExecuteAsync_TenantWithDrift_RecordsRow_AndPublishesEvent` updated to assert outbox-row presence rather than `IEventBus` substitute receipts.
- [ ] **Rollout plan.** Document deploy ordering: platform outbox table + processor scope ship in release N; T-013 publish path migration ships in release N+1 (so processor can drain the new table before publishers start writing to it).
