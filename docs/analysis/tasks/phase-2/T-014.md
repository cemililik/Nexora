## Context

Self-hosted deployments must hot-reload license files without a platform restart
when customers upload a new `.lic` via the admin portal or write to the secret
mount path. Needs a `FileSystemWatcher` (or K8s secret volume reload signal) that
re-validates and publishes a `license.refreshed` event.

See `docs/operations/license-and-helm-upgrade.md` §4.1.

## Acceptance criteria

- [x] Validation triggered on file change at `LicenseFilePath` (default `/var/lib/nexora/license.lic`); polling-loop baseline + SIGHUP short-circuit per ADR-0030. SHA-256 hash compare ensures unchanged files are no-ops.
- [x] New license becomes active with no pod restart — `InMemoryLicenseProvider.Set` swaps via `Interlocked.Exchange`; readers use `Volatile.Read`.
- [x] Invalid file rolls back to previous valid license; admin alerted — `LicenseRefreshFailedIntegrationEvent` fires on validation failure, the provider snapshot is not mutated. Verified by `PerformReloadAttemptAsync_InvalidFile_RetainsPreviousSnapshot_AndPublishesFailed`.
- [x] 7 tests cover: file-not-present no-op, fresh valid file, replacement (old → new), unchanged file no-op, garbage JSON rollback, expired file rollback, bad-then-good recovery.

- 2026-04-25 — In Review — Implementation complete; 7 tests pass. **ADR-0030 deviation:** the ADR specifies polling interval resolved via `IConfigurationResolver` under `platform.license.reload_interval_seconds`. Implementation uses `IOptions<LicenseReloadOptions>` instead because `IConfigurationResolver` is request-scoped (resolves the tenant from `ITenantContextAccessor`) and the reload service is a tenant-less singleton hosted service. The 5–600s range is still enforced (via `IValidateOptions<T>`); operators set the interval via `Licensing:Reload:PollingIntervalSeconds` in appsettings. Recommended follow-up: extend `IConfigurationResolver` with a platform-only resolution path, then port this back if the maintainer prefers strict ADR alignment.
