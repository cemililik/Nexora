## Context

Nightly drift audit compares each tenant's `__ef_migrations_{module}` head against
the expected platform version. Drift logged to `platform_migration_drift` and emits
`platform.migration.drift.detected` event.

See `docs/operations/migration-orchestration.md` §3.

## Acceptance criteria

- [x] `PlatformAuditMigrationDriftJob : NexoraJob<PlatformAuditMigrationDriftParams>` runs `0 5 * * *` UTC (registered via `IdentityModule.ConfigureJobs`).
- [x] Compares actual vs expected migration head per tenant per module via `IModuleMigration.GetMigrationHeadsAsync` (default-impl no-op for Phase 1.5 modules).
- [x] Logs drift to `platform_migration_drift` (new public-schema table; additive DDL in `DevelopmentSeed`).
- [x] Emits `MigrationDriftDetectedIntegrationEvent` — see status-log entry below for the AC4 deviation note.
- [x] Suppresses alerts when drift < 2h old (`Tenant.LastMigrationStartedAtUtc` stamped by `MigrationRunner`; `SuppressionWindow = 2h` in the job).
- [x] Integration test with seeded drift (`PlatformAuditMigrationDriftJobTests` — 6 cases: drift recorded, no-drift skipped, suppression in/out of window, terminated tenant excluded, throwing module isolated).

## Status log

- 2026-04-23 — Not started — Stub created for traceability.
- 2026-04-25 — In Progress — Started implementation. Approach: extend `IModuleMigration` with a default-impl drift-heads method (no-op for Phase 1.5 modules); job iterates tenants × module-migrations and writes drift rows. Suppression window backed by a new nullable `LastMigrationStartedAtUtc` on `Tenant` stamped by `MigrationRunner`.
- 2026-04-25 — In Review — Implementation complete; full Identity test suite green (308 passed). **AC4 deviation:** the spec says "via outbox" but the platform-level outbox infrastructure (a `public`-schema `outbox_messages_platform` polled by `OutboxProcessor`) does not yet exist — the existing outbox is per-tenant. Rather than expand T-013 into platform-outbox plumbing the job publishes via `IEventBus` directly. Drift evidence still lives in `platform_migration_drift` indefinitely so the worst case of a dropped publish is a missed alert, not lost data. Recommended follow-up: a separate task to introduce a platform outbox so this and future platform-level events can ride the standard reliable-delivery path.
